# June 16th 2026
## Focus: Task Management Panel — React Rewrite, Theme System, Bug Resolution

### Context

V1.3 backend has been complete since June 8th. Today closed out the panel frontend, moving from a fragile vanilla JS Web Component to a proper React architecture, and fixed the dashboard theme system which had been silently broken since V1.2.

---

### Panel Architecture Decision — Vanilla JS to React

The original panel was a single-file vanilla JS Web Component. By the time artifacts, session management, hyperparameter tuning, block forms, and mode selection were all in scope, the manual DOM manipulation pattern had accumulated critical bugs: re-render loops on hyperparameter save, `innerHTML = ''` wiping injected state, event handler re-attachment on every render triggering duplicate API calls, and client-side mount state that evaporated on refresh.

The decision was made mid-session to rebuild the panel in React. The Web Component shell is retained as a thin mount point — `connectedCallback` attaches the shadow root and calls `createRoot(container).render(<App apiBase={apiBase} />)`. Everything inside is standard React with hooks. This is the correct pattern going forward for any panel with non-trivial state.

**New panel structure:**
```
tm-panel/
    src/
        panel.jsx          ← Web Component shell
        App.jsx            ← root, mode state, all handlers
        api.js             ← all fetch calls, credentials:include
        components/
            TaskCard.jsx
            BlockForm.jsx
            AddTaskForm.jsx
            ArtifactSection.jsx
            HealthSignals.jsx
            HyperparamPanel.jsx
        hooks/
            useQueue.js
            useSession.js
            useHyperparams.js
    vite.config.js         ← lib mode, IIFE output → panel.js
    package.json
```

Build mirrors the dashboard pattern — `build_panel.sh` uses the base-frontend Docker image, merges package.json, copies source, runs `vite build`, outputs `panel.js` to `frontend/static/`.

### Theme System Fix

The dashboard theme system was silently broken. `dark.css` used Tailwind 4's `@theme {}` directive to declare design tokens, but `@theme` generates Tailwind utility classes — it does not produce standard CSS custom properties on `:root`. The `:root` block in the theme file was referencing `var(--color-bg)` etc that simply didn't exist in the browser's computed style.

**Fix:** Added an explicit `:root {}` block to `dark.css` (and source theme files) with all custom properties declared as standard CSS, making them available to both the dashboard and panel components. Removed `@import "tailwindcss"` from theme files — it was a build directive that caused 404s when the theme was served as a static file. Added `/themes` as a StaticFiles mount in `main.py` before the catch-all SPA route, and added the `<link rel="stylesheet" href="/themes/active.css">` tag to `index.html`.

Theme is now gold/black. `--color-primary: #c8922a`.

---

### Panel Theming — Shadow DOM

Panels use shadow DOM for style encapsulation. CSS custom properties do inherit through shadow DOM boundaries — but only if they're defined on an ancestor element in the regular DOM. Since the theme vars are now on `:root` as standard custom properties, the panel's shadow root inherits them correctly. The panel CSS uses `var(--color-primary)`, `var(--color-bg)` etc directly — no bridge, no hardcoded values, no duplication.

The `@theme` block remains in the theme files for forward compatibility with Tailwind utility generation. The explicit `:root` block runs in parallel and handles the standard CSS inheritance path.

### Bugs Fixed

**HP save infinite loop** — `_saveHyperparameters` triggered a re-render which recreated inputs which fired input events which re-triggered save. Fixed with `_hpSaving` guard. In React rewrite, this is non-issue — state updates are controlled.

**HP float/int** — Backend `bucket_slot_rule` failed on `int('8.03')`. Two-part fix: backend uses `int(float(...))` for all bucket slot casts; frontend `HyperparamPanel` sanitizes values on save (`Math.round` for int params, `parseFloat` for float params), and uses `step="1"` vs `step="0.01"` inputs.

**Complete 400 loop** — Completing a task fired the complete endpoint 20+ times. Root cause: re-render on completion recreated the Complete button, re-attached the event listener, which fired again before the first call returned. Fixed in React with a `completing` state guard.

**`t._mounted` vs `t.mounted`** — The API returns `mounted: bool` but the panel was checking `t._mounted` (a client-side property that was never set). Fixed to use `t.mounted`.

**Active time negative** — `new Date(started_at)` without `Z` suffix caused the browser to interpret the naive datetime as local time (CST), making elapsed time negative by several hours. Fixed with `toUTC()` helper appending `Z` if missing. Backend `datetime.utcnow` replaced with `lambda: datetime.now(timezone.utc)` across all models — applied with targeted sed per file.

**Active time resetting on task complete** — `session.load()` after every task completion was restarting the elapsed timer. Fixed by deriving elapsed time from `started_at` rather than tracking it in state — a tick interval forces re-renders every second, elapsed is computed fresh each render. Timer cannot drift or reset.

**Tasks done not incrementing** — `complete_task` router never incremented `session.tasks_completed`. Fixed by querying the active session after task completion and incrementing. Frontend uses `incrementTasksCompleted()` to update local state optimistically without a reload.

**Session end 404** — Panel showed "Session active" button using stale session state after session ended. Fixed by checking `!session.ended_at` before rendering session controls.

**`MANUAL` block type missing** — Added `MANUAL = "MANUAL"` to `BlockType` enum. No migration needed.

**Mode not threading** — After mount/unmount/complete, the queue reloaded without the current mode, defaulting to `DEEP_WORK`. Fixed by passing mode through all queue action callbacks.

### Features Added

**Break tracking** — Break toggle pauses active timer, starts break timer. Break seconds accumulated client-side, reported to backend on session end as `break_minutes`. Break budget display shows remaining budget. "ON BREAK" banner when active.

**Mode selection** — Dropdown in panel header. Queue reloads for selected mode on change and on all queue-mutating actions.

**Artifacts** — `ArtifactSection` component on each task card. Displays existing LINK artifacts as clickable chips with delete. Inline add form with label + URL fields. Backend add endpoint uses query params, handled separately from JSON API calls.

**Difficulty tag** — Task cards show `difficulty_label` (Ephemeral, Trivial, Light, Moderate, Hard, Severe, Extreme) as a secondary tag.

**Collapsible right column** — Queue health panel defaults to a 28px collapsed sidebar showing the score. Click to expand full health signals and hyperparameters. Click again to collapse.

**MANUAL block type** — Added to enum. Blocks task manually until explicitly unblocked.

### Proxy Architecture

All panel API traffic goes through the dashboard proxy:

```
Browser → /api/panels/{panel_id}/proxy/{path}     → service frontend assets
Browser → /api/panels/{panel_id}/api/{path}        → service API endpoints
```

The browser never contacts service containers directly. Internal Docker network topology is not exposed to the client. Panel `api-base` attribute is set to `/api/panels/task_management/api` by `PanelHost.jsx`.

### Focus Component

`tm-focus/` built alongside the main panel. Same React + Vite lib build pattern. Single `App.jsx` — no separate component files, intentionally minimal. Shows top queued task + mounted tasks, session timer, score. Complete and block actions only — no queue management in focus mode. Outputs to `frontend/static/focus/active_task.js`.
