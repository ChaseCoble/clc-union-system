# Devlog May 25th 2026
## Focus: Orchestrator and Documentation

### Docker Registry

There has already been a decision to keep most of my services in docker containers so I can explicitly control resource consumption. This is manual for now, with it eventually being a duty given to an orchestrator program.
As a result, many of the docker containers have the same underlying structure utilizing python or debian-lite, and the constant repulls present a supply chain vulnerability, so I made the decision to coordinate my own docker registry.
To solve this, I deployed a local docker registry and began to create frequently used images:
- Base python, pulled from the docker image library
- A webserver image built from the base python and fastapi and its dependencies
Others will be added in time

### Supply Chain Record
While building out the registry I identified an opportunity to maintain supervision of the safety of my supply line.
Utilizing the syft tool, I began recording digests and other identification information of all my docker images, as well as keeping the syft sboms, in order to future integrate into a database that can be queried against new and developing CVEs and alert me to any newly discovered vulnerabilities in my services.
Right now its a json file with path pointers, but it will be ingested into a database for surveillance.
